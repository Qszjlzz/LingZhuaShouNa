# 一比一复刻验收规则

## 每页的完成条件

页面只有同时满足以下条件，才可以把状态改为 `通过`：

1. Figma 单页截图和 SwiftUI 同尺寸截图都已保存。
2. 页面层级、首屏可见内容、滚动范围和固定控件一致。
3. 字体、字号、字重、行高、颜色、圆角、描边和间距完成逐项对照。
4. 图片、Logo、图标等资源已确认是原生实现还是独立导出。
5. 所有主要可点击控件都能到达记录中定义的目标页面或状态。
6. 发现视觉不一致时，以截图差异为准回到该页修正，不能因为“看起来差不多”直接通过。

7. 若页面同时存在 Figma Make 代码实现，必须额外与 Make 预览对照一次，区分原始 `ui界面` 设计意图、Make 当前实现和 SwiftUI 最终实现；三者不一致时不得直接采用其中任意一个作为“标准”。

## 对照记录格式

每次检查写清楚：

- Figma 截图路径和导出日期
- SwiftUI 截图路径和构建版本
- 对照尺寸和设备
- 差异项：结构、间距、字体、颜色、图像、交互
- 修复动作
- 复测结果

Make 页面额外记录：

- Make 源码文件和版本
- Make 预览截图路径
- Make 与原始 Figma 的差异
- 哪些差异属于代码实现偏差，哪些差异属于设计稿状态差异

## 迭代门禁

`待单独选中 -> 已单独选中 -> 已导出截图 -> 待实现 -> 对照中 -> 通过`

任何一项出现明确差异，都回退到对应阶段，不把未解决的问题藏在总览页面里。
