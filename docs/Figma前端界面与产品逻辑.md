# 灵爪收纳：Figma 前端界面与产品逻辑

## 结论

灵爪收纳是一款面向真实生活空间的智能收纳 App。它通过拍摄或导入空间照片识别物品，允许用户确认和修正识别结果，再根据整理目标、区域、风格和时间生成收纳方案，最后按步骤完成整理，并沉淀前后对比、空间成果和社区案例。

Figma 文件 `ui界面` 的核心前端闭环是：

```text
空间首页
  -> 拍摄/导入空间
  -> AI 识别物品
  -> 用户确认物品与分类
  -> 生成个性化方案
  -> 选择整理区域
  -> 按步骤执行
  -> 区域完成
  -> 完成照片与前后对比
  -> 成果归档 / 分享到社区
```

## 一级入口

| 入口 | 前端职责 | 用户要完成的事 |
| --- | --- | --- |
| 空间 | 空间驾驶舱和成果档案 | 查看当前空间、进度、已完成成果、进行中的方案 |
| 拍摄 | 采集和识别入口 | 拍摄或导入照片，让系统识别空间和物品 |
| 分类 | 物品分类库 | 浏览、搜索、编辑分类，补充或修正物品 |
| 执行 | 收纳行动流程 | 选择区域，按步骤完成清理、分类和摆放 |
| 社区 | 收纳案例和方案复刻 | 浏览他人案例，查看前后对比，获取同款方案 |
| 个人 | 用户成果和设置 | 查看等级、勋章、日程、提醒和 AI 设置 |

## 1. 空间首页

空间首页不是单纯的信息展示页，而是用户下一步行动的入口。

主要界面状态：

- 空间总览：展示当前空间、收纳进度、已识别物品数量。
- 成果展示：展示已经完成的空间和前后对比。
- 进行中的整理：展示当前方案、完成百分比和继续执行入口。
- 空间详情：查看某个空间的区域、已整理物品和收纳小贴士。
- 区域执行进度：查看当前区域的完成比例、剩余时间和最近活动。

主要动作：

- `开始拍摄`：进入拍摄/识别流程。
- `看看方案`：进入方案生成或已有方案详情。
- 点击空间或成果：进入空间详情。
- 点击进行中的整理：继续执行。

## 2. 拍摄与识别

拍摄页负责把现实空间转成可编辑的物品数据，不直接把识别结果当成最终事实。

主要界面状态：

- 多镜头采集：从两个不同角度采集同一空间，页面显示 `0/2` 至 `2/2` 状态、两张素材缩略图和完成入口；两张素材齐全后进入预览结果。
- AR 扫描：显示实时相机画面、物品边界/遮罩和识别状态；锁定画面后进入识别确认。
- 相机扫描：显示真实空间画面、扫描状态、识别区域和拍摄控制。
- 拍摄结果预览：显示照片、缩略图和识别入口。
- AI 识别结果：显示识别后的物品区域和识别数量。
- 识别确认：显示物品列表、分类标签、疑似问题和可编辑内容。
- 物品编辑：修改物品名称、分类或补充信息。
- 物品补录：识别不完整时，可以重新拍摄、拍照添加或手动输入。

主要动作：

- 拍照/导入照片。
- 确认识别结果。
- 勾选或取消物品。
- 修改物品名称和分类。
- 添加缺失物品。
- 重新拍摄。
- 确认后进入方案生成。

识别结果必须经过用户确认，后续方案不能直接依赖未经确认的识别结果。

## 3. 分类库

分类库是独立于一次整理任务的长期物品档案。它既可以查看已有物品，也可以作为识别流程的补录入口。

本轮前端核对已将分类首页按设计稿重排为：分类库标题、搜索物品或分类、AI 智能识别入口、物品分类网格、最近添加列表。分类网格可进入分类详情；最近添加支持查看、编辑、删除；编辑态显示删除入口；新增入口支持拍摄识别和手动输入。模拟器实测截图为 `app-analysis/screenshots/catalog-figma-final.png`（运行时截图 `/tmp/smartpaw-catalog-final.png`）。

主要界面状态：

- 分类首页：展示分类网格、搜索框、最近记录和底部导航。
- 分类搜索/筛选：按书籍、学习、哲学等分类查看物品。
- 分类详情：展示分类下的物品卡片和数量。
- 分类编辑：进入编辑模式后删除、补充或调整物品。
- 添加新项目选择：选择拍摄添加或手动输入。
- 拍摄添加：用照片识别新物品。
- 手动输入：填写物品名称并选择分类。
- 从物品库添加：从已有分类和最近记录中选择物品。

分类库中的物品可以被识别确认页、方案页和执行页复用。

## 4. 方案生成

方案页把用户的物品数据转成可执行的整理计划。

主要输入：

- 本次整理目标。
- 重点整理区域。
- 已确认的物品和分类。
- 风格或快速标签。
- 参考图片。
- 推荐模式和时间预算。

主要界面状态：

- 方案输入页：确认空间、物品数量和整理目标。
- 风格/标签选择页：选择快速标签和整理偏好。
- 参考图片页：导入或替换风格参考图。
- 推荐模式页：选择快速、智能或更完整的整理方式。
- 方案详情预览：展示整理步骤、目标区域、工具和预计时间。
- 方案生成中：展示生成状态。

方案生成完成后进入区域选择和执行，不应停留在只有文字说明的结果页。

## 5. 执行流程

执行页是产品的核心行动页面。每个步骤都应同时说明当前区域、要处理的物品、所需工具和下一步动作。

主要界面状态：

- 区域选择：根据当前空间选择一个、多个或全部整理区域。
- 步骤 1：清理垃圾。
- 步骤 2：清空桌面并进行物品分类。
- 步骤 3：整理美妆区。
- 后续步骤：取出收纳盒、分区摆放和整理具体物品。
- 当前步骤引导：显示真实空间照片、识别区域、操作说明和工具/摆放示意。
- 区域完成：显示完成标记并进入下一个区域。
- 整理项目进度：展示区域进度、步骤进度、已完成项目和剩余项目。
- 完成照片：记录整理后的空间。
- 前后对比：展示整理前后的照片和成果。

每个步骤的基本动作：

```text
查看当前区域
  -> 查看当前步骤和目标物品
  -> 根据照片/区域提示执行
  -> 标记完成或跳过
  -> 进入下一步
  -> 完成区域
```

## 6. 社区

社区把已经完成的整理方案转成可参考、可复刻的案例。

主要界面状态：

- 案例列表：浏览不同空间和整理风格。
- 案例详情：查看作者、风格、适用空间、前后对比、物品和工具。
- 复刻确认：确认使用当前空间和物品分类生成自己的方案。
- 进入执行：获取同款方案后进入自己的执行流程。

社区方案不是静态图片下载，而是转换成当前用户可执行的整理步骤。

## 7. 个人中心

个人页承接长期使用和成果管理。

主要界面状态：

- 个人主页：收纳等级、完成次数和物品标签数量。
- 勋章墙：展示已解锁和未解锁成就。
- 成就时间线：记录完成过的方案、风格、耗时和日期。
- 日程管理：查看、新增、编辑和删除整理计划。
- 收纳提醒：管理通知权限和提醒状态。
- AI 规划设置：配置本地/云端方案优化能力。

## 页面数量口径

Figma 中有大量 390×844 手机画板，同时存在重复状态、编辑态、底部弹层、完成态和视觉展示板。

- 一级功能入口：6 组。
- 核心页面状态：约 30 至 40 个。
- 如果把弹层、编辑态、识别结果变体和执行步骤逐张算作画板，数量会更多。
- `Page 2` 没有手机界面内容，不计入前端页面。
- `Frame 7`、展板、封面和插件入口不作为 App 页面路由。

## 产品逻辑判断

这个 App 解决的不是“记录物品”或“展示收纳图片”，而是帮助用户完成一次真实的空间整理闭环：

1. 先看见空间问题。
2. 通过照片或相机采集空间。
3. 让 AI 识别物品，但把最终确认权交给用户。
4. 根据确认后的物品和用户偏好生成方案。
5. 把方案拆成区域和步骤。
6. 用照片、区域高亮、工具清单和操作说明指导执行。
7. 用完成照片、前后对比、勋章和社区案例沉淀结果。

因此，前端开发时应优先保证这条主链路完整：

```text
拍摄 -> 识别 -> 确认 -> 方案 -> 区域 -> 步骤 -> 完成 -> 对比
```

分类、社区和个人属于围绕主链路提供复用、激励和长期管理的辅助模块。
