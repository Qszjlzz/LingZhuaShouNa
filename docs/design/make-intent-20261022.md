## 已读范围内的最终决定

### 拍摄、方案和物品确认

V59、V60 用户希望拍后先看空间效果和少量方案，不先面对复杂 AI 对话、参数或完整物品确认列表。V60、V61 合并后的流程：

`完成拍摄 → 理解空间/生成动效 → 1–3 种方案卡片 → 选择或微调 → 看到最终效果并确认 → 方案分区 → 选择先整理区域 → 确认该区物品 → 执行 → 完成留证 → 空间地图反馈`

- 居中大卡片左右滑动、旁侧部分露出，以整理后的空间效果为视觉主体；方案代表不同整理逻辑，不只是换颜色。
- 方案包含名称、简短描述、核心策略/使用特点和主操作，避免大量技术参数。
- 至少一个基础方案不需额外收纳工具；复杂方案先展示并确认工具需求（V61）。
- 微调基于当前方案迭代，不从零重新选；每轮要给新效果反馈，确认满意后才能整理，不能聊完直接跳下一步（V61、V62）。
- 先选区域，再只确认该区物品；区域有名称、数量、优先级和状态，原有分区/执行逻辑保留（V60、V61）。

### 暖色、可爱、治愈的生成动效

V62 用户要增强视觉反馈，助手做了暗黑发光版本；**V64 用户明确否决暗黑，要求回原版或更可爱治愈。** V64 助手摘要改为暖亚麻、咖啡色房间线描、轻柔橙蓝点缀、窗户/植物/地毯、淡扫描和轻盈弹入。色值、时长、尺寸属于助手实现选择，仍需核最终画板。

### 空间碎片与重新点亮

- 新空间来自扫描与收纳完成，首页不应凭空建立；完成后要看得见碎片加入地图的反馈（V65–67）。V65 只有按钮散射仍未满足用户，V67继续接完成信号、奖励卡和落入动效。
- 同一物理空间长期只保留一个节点，后续整理更新方案/版本/颜色/状态，不重复造碎片；变灰表示一段时间未复查，不是失败（V60）。
- 整理助手用于定期提醒，不直接跳拍摄；长时间未更新空间有可发现的点亮入口（V68及后续用户纠正）。
- 点亮独立链路：`拍当前状态 → 评估混乱 → 选原方案微调或新风格 → 按最终方案整理 → 再拍留证 → 原空间恢复最初颜色`。**不得掉落新碎片。**
- 助手提到的14天阈值、波纹数量、弹簧参数、Toast样式是实现提议，不是用户逐项指定。

### 拍后大图预览与连续加拍（V77）

- 仅补拍照/扫描页交互，保持其余布局、视觉和功能。照片清晰、按原比例居中放大，其余区域深灰半透明弱化，配简单入场。
- 大图横向 Carousel、有序号，不用缩略图列表替代主体；最右侧“+ 添加照片”回原相机，新图加入序列并预览。
- 删除切相邻图，删光回相机；重拍替换当前图；完成结束连续拍摄。完整循环需要实际可演示，不能只有静态画面。

### 执行清单与完成留证（V78、V80）

用户要求具体方案后的真实合理跳转。助手摘要连接 `arGuide → task可勾选清单 → reward留证 → onFinish(plan) → 地图`，带所选方案上下文。V78之后恢复到 Add photo preview feature，V80又重复描述修复，因此不能仅据V78的“完成”证明当前链路一直存在；真实拍摄、持久化与归档需当前App验收。

### 入库与自主文件夹整理（V80）

用户限定只改收纳/物品分类，其余页面、功能、交互、视觉、导航、布局保持，不重构整项目：

- 扫描后选部分识别物品入库，原文称“存入云端”；手动填写名称、添加图片，保留原扫描流程。
- 借鉴iPhone操作机制：网格图标和名称、长按轻晃、拖动重排、拖到另一物品建夹、继续拖入已有文件夹。
- 文件夹可打开/改名/加物/移出，另有新建文件夹入口；完成退出并保留排序分类。
- 分类由用户决定，不强制自动分类；入库与整理独立，调整分类不得重复上传或删除物品。
- 操作必须真实可交互；视觉沿用App，只借鉴机制，不照搬iOS系统UI。

助手摘要有四列网格、480ms、2×2文件夹预览、emoji选择、搜索和去重追加；**四列/480ms是实现参数，不是本条用户原话。** 摘要只写emoji＋名称，未证明自定义图已做；全局`storedItems`也不能证明重启持久化或真实云端。
