## 2. 现状盘点（代码事实，已核实）

### 2.1 多张连拍 → 出方案（已修好，但识别结果为空）

链路（已改好，不用重做）：
```
拍摄页快门 → camera.capture → 立刻回缩略图（秒出图）
                            → 识别进后台队列串行跑
点「完成」→ 回顾照片 → 确认识别物品（scan.await 等识别完）→ 生成中 → 方案
```

**她反馈的问题**：拍完之后的方案"还是测试图片的结果"。
原因已查明：代码里到处是 `scannedItems.isEmpty ? currentSpace.detectedItems : scannedItems`——
**识别为空时不报错、不提示，直接静默回落到设计稿自带的示例物品和方案**。
所以"识别不出东西"和"看到假数据"是同一个问题的两面。

### 2.2 识别服务（关键发现：本地家底比想象中厚）

`App/AppDependencies.swift` 注入的是 `YOLOSegmentationScanService()`，
它**不是**单纯固定类别 YOLO，而是组合管线：
`YOLOE 检测 + OCR 文字补救 + EdgeSAM 掩膜精修 + 场景语义校准`。

仓库里还完整保留着早期那套（文件都在、也都在工程里编译）：
- `Services/MobileCLIPRecognitionService.swift` —— MobileCLIP 开放词汇分类
- `Services/EdgeSAMSegmentationService.swift` —— 掩膜精修
- `App/ARMaskOverlay.swift` —— AR 掩膜渲染

模型文件齐全（`Resources/Models/`）：
`yoloe-11s-seg.mlpackage`（可提示/开放词汇）、`yolo11n-seg-640.mlpackage`、
`yolov8s-worldv2.mlpackage`、`mobileclip_s0_image/text.mlpackage`、`EdgeSAM/`。
`Resources/category_embeddings.json` 也在。

**结论：不是"没有模型"，是现有管线跑出来是空的。待验证的假设（按可能性排序）：**
1. Core ML 模型加载/编译失败（本地命令行构建时就出现过 CoreMLModelCompile 卡死），
   `cachedModels` 为空 → `detectItems` 直接 `return []`。
2. 阈值/未知标签过滤太狠，把有效结果滤掉了（`minimumConfidence` still 0.12 / live 0.22，还有 unknown-label gate）。
3. MobileCLIP 语义匹配没启用（`category_embeddings.json` 或文本编码器没加载成功）。
4. 我改的后台识别队列有 bug，结果没并进 `scannedItems`。

**验证方法**（下一步做，别猜）：在真机上打诊断——
输出 `cachedModels.count`、每个模型的 `sourceName/isAvailable`、
一次扫描的原始检测数 → 过滤后数量 → 最终数量，以及 MobileCLIP 是否可用。

### 2.3 AR 扫描（关键发现：真 AR 代码还在，只是没接上）

`App/ScanStudioView.swift` **就是那个"很早以前能正常扫描的 AR 版本"**，代码完好：
```
CameraEngine.liveFrameInterval = 0.55   // 每 0.55 秒抽一帧
→ service.scanLiveImage(frame)          // 实时识别（只跑轻量模型，保证帧预算）
→ ARMaskOverlay 画掩膜
```
它有 `isAR` 模式区分：`arPanel`（AR 模式）vs `photoDock`（连拍模式）。

**但现在拍摄页点 AR 是假的**：`ShootFlow.toggleRecord()` 只抓了一帧静态图，
包装成 `kind:"video"`、标签"AR扫描视频"、时长写死 3 秒，根本不是扫描。
而 `scan.open` 兜底会 present 这个原生 `ScanStudioView` —— **会跳页，违反她的底线**。

**所以 AR 的正确做法**：不是去"打开 ScanStudioView"，
而是把它的**实时识别内核**（抽帧 → `scanLiveImage` → 回传结果+掩膜）
搬到拍摄页里内联实现（复用已经常驻待命的 `CameraPreviewOverlay`），
UI 保持设计稿那样：点 AR 直接开始扫，底部没有快门 dock。

## 4. 识别要怎么才能用（方案对比）

### 方案 1：先诊断本地管线（必做，最快）
把上面 4 个假设逐个验证。很可能只是模型没加载/阈值太狠，改几行就能出结果。
**先做这个，别一上来就换模型。**

### 方案 2：接云端多模态大模型（推荐作为兜底/主力）
App 里已经有「我的 → AI 设置」（`LLMSettings`：endpoint / model / apiKey，DeepSeek 等 OpenAI 兼容格式）。
改造点：让请求体支持 `image_url`(base64) 多模态输入，
可选：通义千问 `qwen-vl-max`、智谱 `GLM-4V`、GPT-4o-mini、豆包视觉版。
- 优点：识别率远高于本地小模型，**不用训练**，比赛前能落地；本地为空时自动兜底，体验稳定。
- 代价：要联网、要 Key、有延迟（1-3 秒）。
- 建议做成**双通道**：本地先跑 → 结果为空或置信度低时自动问云端 → 合并结果。

### 方案 3：自己微调（不推荐现在做）
要采集家居杂物数据集、标注、训练、转 Core ML，周期以周计，比赛来不及。
真要做也建议放在赛后，或者用 YOLOE 的**提示词/类别嵌入**方式低成本提升——
这其实属于方案 1 的范畴（把类别词表换成收纳场景词表）。

### 结论
**1（诊断修复）→ 2（云端兜底）组合执行**；3 从长计议。

## 5. AR 的改造方向（不动 UI）

1. 复用常驻待命的 `CameraPreviewOverlay`（相机已在跑）。
2. 新增"实时扫描"通道：每 0.55s 抽一帧（复用 `CameraEngine` 的抽帧能力）
   → `scanLiveImage` → 通过 bridge 事件把识别结果 + 掩膜坐标推给网页。
3. 网页侧：拍摄页 AR 模式下把结果画成实时标签/遮罩（设计稿样式），
   底部换成 AR 面板（无快门 dock），参考 `ScanStudioView` 的 `arPanel` 结构。
4. 全程不 present 任何原生页。
