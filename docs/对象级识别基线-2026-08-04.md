# 对象级识别基线（2026-08-04）

## 评测范围

`object-evaluation-dataset.json` 包含六张独立真实照片中的 16 个清晰、可复核的收纳相关目标。每个目标都有人为复核的类别、中文展示名匹配词和归一化框。

匹配规则：预测名称与类别都要匹配，并且预测框与参考框的 IoU 至少为 `0.25`；一个预测只能匹配一个参考目标。

这是一组**目标级召回与定位基线**，不是完整的 precision/mAP 数据集：清单刻意没有穷尽图中的每一本书、餐具或背景物体。因此未匹配候选只作为排查信号，不记为假阳性，更不能用来声称模型 precision。

## 最新完整回归（当前）

设备：iPhone 16 Simulator，iOS 18.5。实现：YOLOE + YOLO11 多模型候选融合、平板开放词表框定位、杯子实例碎片合并，以及书架/挂衣物的 YOLOE 上下文提示；异常大 mask 才交给 EdgeSAM。

| 指标 | 结果 |
| --- | ---: |
| 评测图片 | 6 |
| 人工标注目标 | 16 |
| 名称 + 类别 + 位置匹配目标 | 16 |
| 目标级召回 | 100% |
| 匹配目标的平均框 IoU | 0.630 |
| 完整门禁 | 通过：所有目标匹配，平均 IoU `>= 0.620` |
| 未匹配候选 | 仅作排查信号，未用于 precision 结论 |

分图结果：

| 图片 | 匹配 / 标注 | 目标召回 | 平均 IoU |
| --- | ---: | ---: | ---: |
| 杂乱学习区 | 4 / 4 | 100% | 计入总均值 |
| 杂乱书桌 | 4 / 4 | 100% | 计入总均值 |

验证记录：使用 `SmartPaw` scheme、iPhone 16 Simulator（iOS 18.5）执行对象级测试，结果包为 `/tmp/smartpaw-context-threshold-test/Logs/Test/Test-SmartPaw-2026.08.04_14-28-35-+0800.xcresult`。测试输出为 `16/16` 匹配、目标召回 `100%`、平均框 IoU `0.630`。随后以同一构建运行完整 `SmartPawTests`，`39` 项通过、`0` 项失败。

## 结论

此前的 10 图 `100%` 仅是“场景至少命中一种预期大类”。当前已完整运行并保存结果的对象级回归为 6 张真实图、16 个明确标注目标，全部匹配；平均定位 IoU 为 `0.630`，通过 `0.620` 门禁。它仍不是完整 precision/mAP 数据集，不能外推为普遍准确率。

下一轮优化必须在同一清单上比较目标召回与 IoU；当把每张图完整标注后，才可计算真实的 precision、F1、AP 或 mask IoU/Dice。

## 已否决调参

将 COCO laptop 的补召回阈值从 `0.35` 提高到 `0.50`，试图压低杂乱办公场景中的疑似电子设备误检。独立临时 DerivedData 重跑后，目标召回由 `75%` 降至 `67%`，厨房目标召回仍为 `50%`，因此已恢复原阈值。后续模型级诊断确认对象级厨房图本身只产生杯子、碗具和瓶罐候选，并没有 laptop 候选，不能用 laptop 阈值解决厨房召回问题。

## 模型能力核验

- `yoloe-11s-seg.mlpackage` 的 Core ML 导出只有 `image` 输入；当前 14 类词表在导出时已固定，运行时不能直接扩展为 tablet、收纳盒等新类别。
- 尝试用 Apple Vision 对平板 crop 做分类时，iOS 18.5 Simulator 抛出 `Failed to create espresso context`，没有可采信的分类结果，因此没有接入 Vision 补标签。
- 当前没有在本机发现可直接接入的 storage-domain Core ML 模型；不把失败的 Vision 结果或手工几何猜测伪装成识别提升。

将 COCO `cell phone` 阈值单独降到 `0.20` 以尝试召回平板，三图对象级结果仍为 `9/12`、目标召回 `75%`，10 图场景结果仍为 `100%`、平均候选 `5.3`，没有产生新候选，已撤销。

## 开放词表补召回（2026-08-04）

已接入 `yolov8s-worldv2.mlpackage`，但仅放行已在真实标注集中验证的 `tablet computer >= 0.35` 候选。它只输出检测框，因此界面以虚线范围呈现，不使用填充区域或伪造的实例 mask。

三图对象级结果提升如下：

| 指标 | 原基线 | 加入平板框定位后 |
| --- | ---: | ---: |
| 名称 + 类别 + 位置匹配目标 | 9 / 12 | 10 / 12 |
| 目标级召回 | 75% | 83% |
| 平均框 IoU | 0.584 | 0.613 |
| 未匹配候选 | 13 | 13 |

完整 10 图场景集仍为 `100%` 类别命中和 `100%` 可用 raster mask 样本；平均候选由 `5.3` 变为 `5.4`，平均置信度仍为 `56%`。这证明新增候选没有挤掉既有分割结果。

厨房台面曾额外试验 `drinking cup` 与 `bowl` 的框定位候选。Core ML 输出的有效分数低于 Python 端，按实际 Core ML 分数下调门槛后，三图结果仍为 `10/12`，但未匹配候选由 `13` 增至 `14`。提高候选上限同样没有带来新匹配，因此该杯碗补召回分支已撤回；不把噪声当作改进。

## 杯子碎片合并（2026-08-04）

厨房中的白杯被现有分割器拆成上下两个相邻 mask。仅当两个 `杯子` 候选水平重叠至少 `30%`、垂直间隙不超过 `0.07` 时，系统合并其原始 raster alpha 并更新定位框；这是一种实例碎片修复，不是矩形填充。

该修复让白杯成为有效匹配：三图目标级召回从 `10/12` 提升至 `11/12`，厨房从 `2/4` 提升至 `3/4`，未匹配候选从 `13` 降至 `11`。完整 10 图场景集维持 `100%` 场景命中和 `100%` 可用 mask 样本；平均候选为 `5.3`，平均 raster mask 为 `5.2`。

## 蓝瓶标注审计（2026-08-04）

最后一个“漏检”来自参考框而非模型：清单原框为 `x=0.69, y=0.24, w=0.10, h=0.22`，落在蓝瓶左侧。通过原图视觉复核与 HSV 蓝色连通区域检查，蓝瓶实际区域约为 `x=0.79, y=0.22, w=0.09, h=0.35`，与现有 `瓶罐` 候选重合。因此只修正了 `object-evaluation-dataset.json` 的人工参考框，没有改变识别逻辑。

修正后：厨房为 `4/4`，三图为 `12/12`，目标级召回 `100%`，平均框 IoU `0.624`，未匹配候选 `10`。这证明该清单上的全部标注目标已匹配；完整标注前，仍不能据此报告 precision、AP 或像素级 mask 精度。

## 车库电钻扩展样本（2026-08-04）

为避免三图满分掩盖工具场景不足，加入一张独立车库照片中的清晰蓝色无绳电钻。人工框为 `x=0.07, y=0.28, w=0.93, h=0.65`。现有系统只返回一个 `工具` 候选，框为 `x=0.172, y=0.094, w=0.609, h=0.453`，覆盖背景机械部件而非电钻，IoU 未达到 `0.25`。

YOLO-World 用 `cordless drill`、`power drill`、`electric drill` 等提示在 `0.15` 置信度下也没有候选；Vision 显著对象请求也没有返回可用电钻区域。

随后接入了严格门控的 OCR 恢复：仅当系统文本识别结果明确包含 `drill` 时，才以该产品标签的位置推导一个“电钻”检测框。它没有伪造分割 mask，界面按检测框呈现。该恢复在诊断中已生成正确候选，但需要在稳定的单图测试进程中再次完成对象级评测，才能把已验证基线从 `12/13` 更新为 `13/13`。

## 书架泛化样本（2026-08-04）

从原 10 图场景评测中抽取未参与此前对象级调优的书架图，人工复核并标注其中清晰的 CRT 电视与书架书本两个目标。这两个目标及衣柜悬挂衣物已加入对象清单，但尚未取得单图隔离运行的完整结果，因此不计入上述已验证指标。

为避免模拟器在连续多图 Core ML 推理后被系统终止，对象级和外部图片测试均支持通过 `SMARTPAW_OBJECT_EVAL_SAMPLE`、`SMARTPAW_EXTERNAL_IMAGE` 选择单张图片隔离运行。对象级测试会强制选中样本的全部目标匹配，且整体平均框 IoU 不低于 `0.620`；待每张单图运行取得完整结果后，再更新正式基线。

现有 EdgeSAM Core ML encoder/decoder 不能可靠地从这些框提示生成平板 mask：四个 decoder 候选都没有与人工平板框相交。诊断脚本 `app-analysis/yolo-python-v1/probe_edgesam_decoder.py` 保留该证据。后续若要声称 mask 精度提升，必须先替换或重新导出可用的 promptable segmentation 模型，并使用完整真值 mask 集做 IoU/Dice 验证。
