# 识别链路：本地 + 云端双通道（2026-09-26 实现）

## 为什么要改

- 拍照后经常「什么都没识别到」。本地管线（YOLOE / YOLO11 分割 + EdgeSAM + 语义校准）在真机上
  有两种失败方式：CoreML 模型没编译进 bundle（`cachedModels` 为空 → `detectItems` 直接返回 `[]`），
  或严格过滤（必须有精确轮廓 + 面积阈值）把候选全滤掉。
- 之前「认不出」时前端会静默回落到设计稿示例数据，看起来像识别了，实际是假数据。

## 现在的链路

```
拍照 / AR 取帧
      │
      ├─► 本地 YOLOSegmentationScanService
      │     严格口径（精确轮廓）→ 空则降级宽松口径（有框就算，最低置信 0.25）
      │     → 仍空则 CoreMLSegmentationScanService（Vision 分类 + OCR）
      │
      └─► 云端 CloudVisionRecognitionService（只在配置且需要时调用）
             多模态大模型直接输出中文物品名 + 类别 + 位置

      ▼
RecognitionRouter 合并：名称/类别用云端，位置轮廓沿用本地 mask，
本地多认出的高置信物品补在后面。
```

## 使用方式

1. 打开 App → 我的 → 设置（AI 设置）。
2. 点一个预设（推荐「阿里云百炼 · 通义千问 VL」，模型 `qwen-vl-max`），或直接填接口地址与模型。
3. 填 API Key → 打开「启用云端 AI」→ 保存。
4. 回到拍摄拍照：识别结果会带上云端给出的中文物品名。

不填 Key 也能用：本地模型负责识别，只是准确率依赖小模型。

## 诊断

- 拍摄确认页：识别为空时会直接写明原因（云端未开启 / 模型加载数 0 / 本次本地与云端各识别出几件）。
- bridge `scan.diagnose` 返回：`modelCount`、`models`、`cloudEnabled`、`visionModel`、`detail`。
- Xcode 控制台关键字：
  - `SMARTPAW_MODEL_LOADED count=... names=...`（启动时打印，count 为 0 说明模型没打进 bundle）
  - `SMARTPAW_MODEL_LOAD_FAIL ...`（某个模型编译失败）
  - `SMARTPAW_SCAN cloud=N names=...`（云端返回条目）
  - `SMARTPAW_SCAN cloud-error ...`（云端失败原因）
  - `SMARTPAW_VISION_HTTP 4xx ...`（接口返回错误码，通常是 Key 或模型名不对）

## 已知边界

- 云端识别按批只调用一次（连拍第一张），其余照片走本地，避免每张都等网络往返。
- AR 实时扫描：本地逐帧，云端每 4 秒补一次，结果合并进叠加层。
- 模型必须是多模态（带视觉）模型；纯文本模型（如 deepseek-chat）识别不了照片。
