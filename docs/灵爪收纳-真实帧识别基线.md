# 灵爪收纳真实帧识别基线

记录时间：2026-07-22

## 验收原则

- 只使用项目已有真实视频帧资产，不使用生成文字图证明视觉/AR 能力。
- 基线目标不是假装所有物品都能准确识别，而是记录当前 YOLO 实例分割 + DeepLab/Vision 兜底管线能稳定给出的结果。
- 识别候选必须至少具备：非空名称、可确认分类、`arHint` 区域、可渲染 `arMask`。

## 本地分割模型

- 主模型：`Resources/Models/yolo11n-seg.mlpackage`
  - 来源：Ultralytics YOLO11n-seg，已导出为 Core ML ML Program。
  - 接入服务：`YOLOSegmentationScanService`
  - 运行策略：优先解析 YOLO 输出的检测张量 `1x116x8400` 与 mask proto `1x32x160x160`，做置信度筛选、NMS、mask 合成，然后输出 `DetectedItem.arHint/arMask`。
- 兜底模型：`Resources/Models/DeepLabV3Int8LUT.mlmodel`
- 来源：Apple 官方 Core ML Models 页面，DeepLabV3 Int8 LUT。
- 接入服务：`CoreMLSegmentationScanService`
- 兜底策略：YOLO 无结果时回退到 DeepLabV3；DeepLab 输出为空时继续回退到 `VisionScanService` 的前景实例 mask / 显著区域 / 矩形区域 / OCR 管线。

- 坐标修复：图片改为按比例完整显示，mask 在图片实际显示矩形内布局，避免 `scaledToFill` 裁切导致的整体错位。

与参考视频相比仍未达标的部分：

- 多本书的标签拥挤，缺少碰撞避让。
- 部分 mask 边缘仍粗糙，电脑和桌面物体存在粘连或漏检。
- YOLO11n-seg 是 COCO 通用模型，尚不能稳定识别视频中的“垃圾堆/待处理区域”等收纳语义。
- 当前结果证明了模拟器端自动实例分割链路可用，但不能表述为已经达到参考视频的识别精度。

## 2026-07-22 专业 CV Agent 复审与修正

独立移动端 CV Agent 对 Swift 解码结果与 Ultralytics Python 输出进行了对照，确认并修复：

- 输入由 Vision `.scaleFill` 拉伸改为官方 letterbox：等比例缩放、RGB 114 填充，再直接调用 `MLModel.prediction`。
- letterbox 的 padding 和内容尺寸随推理结果保存，box 与 proto mask 会去除 padding 后映射回原图比例。
- SwiftUI mask 不再套用会二次居中的外层 `frame`，改为按真实图片矩形中心定位。
- NMS 改为同类别抑制；不同类别的重叠物体不会互相删除。
- 移除 3% 最小边长过滤，保留笔、遥控器、线缆等小物体候选。
- 1280 模型为空时自动级联 640 模型，不再直接退化成粗多边形兜底。

## 已知边界

- YOLO11n-seg 是 COCO 通用实例分割模型，不是宿舍收纳专用模型；它已经明显优于纯框选/DeepLab 语义分割，但仍会漏掉杂乱全景里的部分物体。
- DeepLabV3 的类别来自通用语义分割，不是宿舍收纳专用类别；它现在只作为 YOLO 无结果时的 mask 兜底。
- iOS 模拟器里部分 Vision/ML 后端仍可能出现 `Failed to create espresso context` 日志；当前服务不会因此断流，会降级到真实 observation 驱动的软轮廓 mask。
- 若要进一步接近视频里的高精度贴边观感，下一步应继续尝试 FastSAM-s / MobileSAM，或用真实宿舍收纳照片微调 YOLO-seg。

## 自动识别产品原则

- 主流程不要求用户移动、缩放或确认 mask。
- 低置信度结果宁可不展示，不使用矩形框或伪造软轮廓凑数量。
- 所有照片自动执行 1280 YOLO -> 640 YOLO -> 通用视觉兜底的级联流程。
- `testManualRegionFineTuneFeedsPlanningARMask` 仅保留为旧数据兼容测试，不代表当前主流程需要用户调整。

## 下一阶段模型增强

专业模型部署 Agent 给出的优先级：

1. EdgeSAM-3x：官方提供 Core ML Encoder/Decoder，iPhone 14 官方单 prompt 数据约 38.7 FPS；许可证仅允许非商业使用，适合当前比赛原型。
2. MobileSAM：Apache-2.0，可商业；社区 Core ML 包约 23 MB，官方 iPhone 14 数据约 4.9 FPS。
3. SAM2.1 Tiny：Apache-2.0，质量对照候选，但 Core ML 包体约 76 MB，移动端成本更高。
4. FastSAM：实际许可证为 AGPL-3.0，且仍属于 YOLO-seg 路线，不优先。

目标接入方式：`YOLO 分类与 box -> box 自动扩张 2%–5% -> EdgeSAM/MobileSAM box prompt -> stability score 选择 mask -> 回映射原图 -> mask IoU 去重`。全程自动，不要求用户调整。

当前环境从 Hugging Face 下载 EdgeSAM 官方 Core ML 包连接超时；GitHub MobileSAM 20 MB 包下载速度约 10 KB/s，未能在本轮可靠取得完整权重。因此本轮没有把未下载、未验证的 SAM 模型写成已接入。

验收方式：

- 仍使用 `SmartPawVideoPain`、`SmartPawVideoScan`、`SmartPawVideoGuide` 作为固定基线。
- 增加用户现场桌面/床边/衣柜照片。
- 真机复测 ARKit 相机帧延迟、发热、mask 抖动和空间对齐。
