# 微调方案的真实效果图确认

日期：2026-10-23。此记录覆盖 React 微调链路的请求与状态行为，不证明供应商生成图片的物品保真，也不替代最终真机验收。

微调页此前只在聊天后展示整理前照片，偏好仅改变方案名称和最后两条描述，确认会直接进入整理分区。现在全部用户偏好进入生产生图请求的 goal、changes，以及后续可执行方案的 goal。每次新增偏好都会使旧效果图失效。

主按钮先由用户触发生成当前方案效果图；收到并加载当前方案的实际返回图片后，按钮才变为“确认效果图，继续整理”。页面支持与原图对比、取消、失败重试，并提供明确的“先使用文字方案继续整理”入口。延迟返回的旧方案图片不能覆盖新偏好。聊天中的卡片保留原有动画；没有当前真实返回图片时，标为“整理前照片”和“待生成效果图”。

验证结果：

- `node --test tests/tunePlan.test.mjs tests/imagePreview.test.mjs`：4/4 通过。包含三条以上偏好完整传递、请求身份变化、基础方案不被修改。
- `npm run build`：成功，Vite 6.3.5；有既有的大包体积提示。
- `tests/tune-preview-ui-smoke.mjs`：390 与 320 CSS px 共 6 项检查通过，errors=[]。检查偏好请求、生成后明确确认、原图对比、新偏好失效旧图、失败重试、旧请求延迟结果隔离及进入整理分区。
- `tests/image-preview-ui-smoke.mjs`：原分区生图 6 项检查通过，errors=[]。覆盖分区请求、切换取消、失败重试及缓存恢复。
- 已目视检查 320 px 截图，底部确认与对比按钮可见，无文档横向溢出。

浏览器证据位于 `docs/quality/tune-preview-ui-20261023/results.json` 和同目录的 390/320 截图。测试环境为桌面 Chromium、SVG 测试图和原生桥接 fixture，未调用真实供应商，未连接手机。供应商是否按偏好保留全部物品，仍需结合 AI 输入图的真实 edit 结果独立判断。最终内嵌网页资源由主任务统一重建同步。
